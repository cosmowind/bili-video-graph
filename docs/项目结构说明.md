# 项目结构说明

## 目录组织

```
bili-take-tree/
├── src/                     # 核心源代码
├── data/                    # 数据文件
├── output/                  # 生成的输出文件
├── docs/                    # 项目文档
├── ref/                     # 参考资料
├── run.py                   # 主运行脚本
├── test_demo.py            # 演示脚本
├── requirements.txt        # Python依赖
└── README.md               # 项目说明
```

## 详细说明

### src/ - 核心源代码

存放项目的核心代码文件。

| 文件 | 说明 | 用途 |
|------|------|------|
| `data_processor.py` | 数据处理脚本 | 将CSV数据转换为图谱节点和边 |
| `graph_generator.py` | 图谱生成脚本 | 使用模板生成HTML图谱 |
| `graph_template.html` | HTML模板 | 可视化图谱的前端模板 |
| `config.py` | 配置文件 | 集中管理样式和参数配置 |

**为什么放在src？**
- 这些是项目的核心逻辑代码
- 便于版本控制和代码复用
- 清晰的代码组织结构

### data/ - 数据文件

存放输入数据和中间处理结果。

| 文件 | 说明 | 来源 |
|------|------|------|
| `videos.csv` | 原始视频数据 | RPA工具采集 |
| `videos_sample.csv` | 示例数据 | 项目自带 |
| `graph_data.json` | 图谱数据 | 脚本生成 |

**注意事项：**
- `videos.csv` 需要自行采集，不包含在版本控制中
- 示例数据用于快速测试
- JSON文件是中间产物，可以重新生成

### output/ - 输出文件

存放生成的HTML图谱文件。

| 文件 | 说明 | 生成方式 |
|------|------|----------|
| `graph.html` | 正式图谱 | `python run.py` |
| `demo_graph.html` | 演示图谱 | `python test_demo.py` |

**特点：**
- 独立的HTML文件，可直接在浏览器打开
- 包含所有必要的CSS和JavaScript
- 可以分享给他人查看

### docs/ - 项目文档

存放所有项目文档和说明。

| 文件 | 说明 | 内容 |
|------|------|------|
| `README.md` | 详细说明 | 完整的项目介绍 |
| `使用说明.md` | 使用指南 | 详细的使用步骤 |
| `RPA采集指南.md` | 采集指南 | 数据采集方法 |
| `项目总结.md` | 项目总结 | 技术总结和优化方向 |
| `项目结构说明.md` | 本文件 | 目录结构说明 |

**为什么独立docs目录？**
- 文档与代码分离，便于维护
- 方便生成文档网站
- 清晰的信息架构

### ref/ - 参考资料

存放项目的参考资料和原始素材。

| 文件 | 说明 | 用途 |
|------|------|------|
| `戴锦华_侧边栏增强版图谱.html` | 原项目参考 | 学习和对比 |
| `prompt.txt` | 对话记录 | 需求和讨论记录 |
| `*.png` | 截图 | 效果展示 |

**特点：**
- 不参与项目运行
- 仅供参考和学习
- 可以安全删除而不影响功能

### 根目录文件

| 文件 | 说明 | 用途 |
|------|------|------|
| `run.py` | 主运行脚本 | 一键处理数据并生成图谱 |
| `test_demo.py` | 演示脚本 | 使用示例数据快速测试 |
| `requirements.txt` | Python依赖 | pip安装依赖包 |
| `README.md` | 项目说明 | 快速了解项目 |

## 文件依赖关系

```
run.py
  ├─> src/data_processor.py
  │     └─> data/videos.csv
  │           └─> data/graph_data.json
  └─> src/graph_generator.py
        ├─> data/graph_data.json
        └─> src/graph_template.html
              └─> output/graph.html
```

## 工作流程

1. **数据采集**：使用RPA工具 → `data/videos.csv`
2. **数据处理**：`run.py` 调用 `data_processor.py` → `data/graph_data.json`
3. **图谱生成**：`run.py` 调用 `graph_generator.py` → `output/graph.html`
4. **查看结果**：浏览器打开 `output/graph.html`

## 自定义扩展

### 添加新功能

1. 在 `src/` 中创建新的Python模块
2. 在 `run.py` 中导入并调用
3. 更新 `docs/` 中的相关文档

### 修改样式

1. 编辑 `src/config.py` 修改配置
2. 或直接编辑 `src/graph_template.html` 修改模板

### 添加新文档

1. 在 `docs/` 中创建新的Markdown文件
2. 在 `README.md` 中添加链接

## 版本控制建议

### 应该提交的文件

- `src/` 所有代码
- `docs/` 所有文档
- `ref/` 参考资料
- 根目录配置文件
- `data/videos_sample.csv` 示例数据

### 不应该提交的文件

- `data/videos.csv` 实际采集的数据
- `data/graph_data.json` 中间文件
- `output/*.html` 生成的文件
- `__pycache__/` Python缓存
- `.vscode/` 编辑器配置

## 部署建议

### 本地使用

直接运行脚本即可，无需额外配置。

### 分享给他人

1. 打包整个项目目录
2. 或只分享 `output/graph.html`（独立文件）

### 服务器部署

1. 安装Python环境和依赖
2. 设置定时任务自动采集和生成
3. 使用Web服务器（如Nginx）托管HTML文件

## 常见问题

### Q: 为什么不把所有文件放在根目录？

A: 分目录组织有以下好处：
- 清晰的职责划分
- 便于查找和维护
- 符合项目开发规范
- 易于扩展和协作

### Q: 可以改变目录结构吗？

A: 可以，但需要同步修改：
- 脚本中的路径引用
- 文档中的路径说明
- 配置文件中的路径

### Q: 如何添加新的数据源？

A: 
1. 在 `src/data_processor.py` 中添加新的数据读取逻辑
2. 在 `src/config.py` 中添加相关配置
3. 更新 `docs/` 中的文档
